# CourtFlow V0.3 Alpha · 球权驱动技术统计

## 状态

**可交互原型，非正式赛用版本。** 2026-10-22 原型已在 Chromium 桌面和 390px 手机宽度进行流程测试。请勿把它作为正式比赛唯一数据来源。

## 已落实的交互与数据逻辑

- **中央篮球场**：A队固定左半场、B队固定右半场，上排各2人，下排各3人，竖直中线；A/B 双队场上队员节点、篮球图标随持球者移动，无持球者时中圈显示；活球未归属闪烁、死球静止；文字显示「A1发球」「A1 → A2」「罚球1/2」「待发球」等。
- **球权状态机**：待发球→选择发球者→接球队员；当前持球时点击同队人为传球，点对手为「原持球者失误＋对方抢断」，生成一条原子事件。投篮命中转待发球，投失转待归属。
- **投篮命中**：投篮记分；同一窗口设置助攻成立/无助攻/延后与有无犯规。助攻候选使用最后传球者，不能自动把个人突破认定为助攻。
- **投篮未中**：有犯规/无犯规/取消。被投篮犯规的投失不计运动战出手；无犯规则进入盖帽选择，继而篮板/出界选择。出界时选择发球球队，记录球队篮板和待发球。
- **犯规及罚球**：防守犯规、进攻犯规、其他犯规（2026 破坏性/恶意/两类技术/席位技术）。记录0~3罚、执行罚球者、罚后保留发球权的球队；罚球前可批量换人，默认不能换下实际执行罚球者；罚球结果暂存，末罚需要二次确认。
- **换人**：每队固定演示名单12人（5+7）；点场上队员→点替补，连线式批量提交；替补沿用原下场球员的球场节点位置，其他队员不重排；可处理5犯离场，无合法替补时人数可少于5。
- **其他**：普通失误、出界、违例、争球、交替球权箭头、球队暂停、突发情况暂停（唯一允许覆盖其他模态窗口的紧急入口）、节次切换、加时、未知球员比分校正。
- **事件日志**：撤销、编辑、插入、删除；修改后重算统计和球权，显示链路冲突；保存至浏览器 localStorage，导出完整 JSON、事件 CSV、技术统计 CSV。
- **跨端**：纯静态文件、自适应布局，没有外部 JS、图片或网络请求；支持 Windows / Android / iPhone 浏览器打开。不同设备**尚不能自动同步**。

## 已确认并实现：罚球违例三选项

- **撤销违例**：返回原罚球/篮板窗口，事件数据不变。
- **取消本罚**：本罚作废且不重罚；该罚不计罚球出手、命中或得分。若取消发生在已进入末罚篮板界面，原罚球组在新确认提交前保持不变；确认后原组记录标记作废，以免双计。
- **重新罚球**：撤回本罚结果并重新录入；确认后旧组原始结果标记作废，新的有效罚球只计一次。
- 本罚取消后没有明确发球方时，只进入「待发球」状态，不擅自推断后续发球方。用户点击发球队员后确定下一球权。此为原型交互定义；正式比赛的实际罚则仍以裁判判罚为准。
- 延迟鸣哨场景：末罚未中进入篮板窗口后，仍可通过「违例」回溯处理。

## 球场布局修复（V0.3.1）

- 球场底图改为左右半场，篮筐设在场地左右两端，**中线竖直**。
- A队在左：上排 A1/A2，下排 A3/A4/A5；B队在右：上排 B6/B7，下排 B8/B9/B10。
- 移动端仍保持相同左右方向，不改成上下阵列；球权图标和全部节点保持可点击。
- 换人后只替换原球员在阵列中的位置，不重排其他人。

## 原型仍待工程化的功能

- 精确的2026犯规累计取消资格规则、暂停机会及罚球特殊处罚完整判定

- 生产级持久化（IndexedDB + 定期备份）、跨设备同步
- Excel/PDF 正式报告输出（当前提供 CSV/JSON）

## 使用方法

将 `courtflow-v03-1.html` 存到电脑或手机并在浏览器打开，推荐优先在桌面测试完整流程。手机可通过网页服务器访问或下载 HTML；部分 iOS 文件预览不能运行交互脚本。开始时球处在中圈「待发球」，先点一名场上球员再点接球队员；之后从侧栏点投篮等事件。系统不会自动处理所有 FIBA 裁判规则，所有特殊判罚以实际裁判决定为准。
